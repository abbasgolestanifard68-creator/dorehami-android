# قوانین کار مستقل تیم ایجنتی

هدف: تیم ایجنتی جلوتر از مالک کار کند، بدون اینکه هر قدم منتظر اجازه بماند و بدون اینکه کار خطرناک یا گران انجام شود.

## سه سطح اختیار

**سطح الف — بدون پرسیدن انجام شود:**
- ساخت شاخه `claude/<موضوع>` و کامیت در آن
- کد اندروید، تست‌ها، مستندات، طرح بک‌اند (فقط نوشتنی)، پیش‌نویس متن‌های مارکتینگ و سیاست‌ها
- بازبینی امنیت و QA روی کد موجود
- خواندن نتیجه CI از روی Pull Request و رفع خطای ساخت

**سطح ب — پیشنهاد بده، منتظر تأیید مالک بمان:**
- Merge کردن هر PR در `main`
- تغییر محدودهٔ محصول، قرارداد API که بک‌اند تأیید کرده
- هر چیز پولی یا اشتراکی (دامنه، سرور، SDK پولی، تبلیغ)، انتخاب فناوری بک‌اند
- افزودن وابستگی جدید به اپ

**سطح ج — هرگز:**
- کامیت مستقیم روی `main`، گذاشتن راز (کلید، رمز، توکن، کلید release، فایل مجوز) در مخزن
- انتشار عمومی اپ، انتشار متن حقوقی بدون تأیید، حذف داده، عوض کردن عمومی/خصوصی مخزن
- ادعای «آزموده‌شده» بدون نتیجهٔ واقعی CI یا تست روی گوشی

## حلقهٔ کار

1. از `docs/BACKLOG.md` بالاترین تسک که **مسدود نیست** را بردار.
2. شاخه بساز، کار را انجام بده و کامیت کن.
3. اگر کد است، نتیجهٔ CI را بخوان (نیاز به PR دارد) و تا سبز شدن اصلاح کن.
4. بازبینی توسط ایجنت دیگر (QA یا امنیت) انجام شود.
5. وضعیت را در `docs/BACKLOG.md` به‌روز کن.
6. اگر تسک به کاری از سطح ب یا مسدودکنندهٔ مالک رسید، در بخش «منتظر مالک» بگذار و سرانجام به تسک بعدی برو.
7. در پایان هر دوره گزارش فارسی کوتاه: انجام شد / مسدود / قدم بعدی.

## محدودیت‌های واقعی (صادقانه)

- **ایجنت فقط وقتی کار می‌کند که اجرا شود.** در گفتگوی چت Claude همان موقع که پیامی می‌فرستی کار می‌کند؛ بدون پیام، در پس‌زمینه کاری انجام نمی‌شود. برای کار بدون حضور نیاز به ابزار دیگری است (Claude Code روی سیستم پشتیبانی‌شده، یا اجرا از طریق GitHub Actions با کلید API، که هزینه دارد و نیاز به مجوز Workflows دارد).
- **ساخت PR نیاز به دکمهٔ Submit مالک دارد** (ابزار فرم نشان می‌دهد). یا مالک از لینک compare گیت‌هاب PR می‌سازد.
- ایجنت‌ها دامنه نمی‌خرند، مجوز نشان نمی‌گیرند و روی گوشی تست نمی‌کنند.
